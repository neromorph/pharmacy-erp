# Map: SIPNAP Reporting v2

## Destination

Extend SIPNAP v1 with what the official SIPNAP report form actually requires: Pemusnahan (destruction) status with BAP fields, split Pemasukan/Pengeluaran sources, harder field-level validation, and an export history screen.

## Notes

- **Tracker**: this vault. Format per `pharmacy-erp-vault/agents/issue-tracker.md`.
- **Domain**: pharmacy compliance follow-up. Read `CONTEXT.md`, `AGENTS.md`, `pharmacy-erp-vault/sipnap-reporting/map.md` (v1), and the official manual at `sipnap.kemkes.go.id/data/manual_book_apotek.pdf`. ASD-STE100 in all output.
- **Official report fields (from the manual, LAPORAN > Upload/Input Pelaporan)**: Periode; Status Pelaporan (Nihil / Periodik); Status Transaksi (Ada Transaksi / Tidak Ada Transaksi); Stok Awal; Pemasukan Dari PBF; Pemasukan Dari Sarana; Pengeluaran Untuk Resep; Pengeluaran Untuk Sarana; Status Pemusnahan (Tidak Ada Pemusnahan / Ada Pemusnahan); Nomor BAP; Tanggal BAP; Jumlah yang Dimusnahkan; Stok Akhir.
- **Scope lock (pending grilling)**: v2 adds Pemusnahan tracking, the Pemasukan/Pengeluaran splits, the IN/HB checks, and the export history screen. No backend scheduler, no multi-branch.

## Decisions so far

- SIPNAP v1 (base): `get_sipnap_report` RPC returns transactions + per-product Saldo Awal/Pemasukan/Pengeluaran/Status Pemusnahan/Saldo Akhir; hard-block on missing doctor/patient fields; `/reports/sipnap` month picker + inbox + CSV; `sipnap_exports` audit row. See `pharmacy-erp-vault/sipnap-reporting/map.md`.
- [Pemusnahan model](issues/01-pemusnahan-model.md) — new `stock_destructions` + `stock_destruction_items` (bap_number, bap_date, witness_names, reason EXPIRED/DAMAGED); hard batch decrement at record time; OWNER + PHARMACIST only; BAP required at save.
- [Pemasukan/Pengeluaran splits](issues/02-pemasukan-pengeluaran-splits.md) — Dari PBF = `suppliers.is_pbf=true` receipts; Dari Sarana = the rest; Untuk Resep = `sale_type='RESEP'`; Untuk Sarana = new `sale_type='SARANA'` (facility name as patient); report exports 4 un-merged numbers.
- [IN/HB checks](issues/03-in-hb-checks.md) — drop IN/HB. Three hard-blocks: Continuity (Stok Awal == previous month's snapshot Stok Akhir; no snapshot = pass), Negative (Stok Akhir < 0), BAP (destroyed qty without bap_number).
- [Export history](issues/04-export-history-screen.md) — tab on `/reports/sipnap` [Generate Report] [History]; columns Month/Year/Generated At/Generated By/Row Count/Hash; exact CSV pushed to Storage bucket `sipnap-archives` (tenant RLS), URL on the row; re-download serves the stored file; newest-first with pagination.

## Not yet specified

- Destruction value fields (unit cost not required for SIPNAP v2).
- SARANA sale flow details (reuse of patients table for facility names).
- Whether history pagination is server-side or client-side.

## Out of scope

- Background scheduler / auto-submit to SIPNAP.
- Multi-branch.
- SATUSEHAT, BPJS/JKN.
- General ledger / double-entry accounting.
