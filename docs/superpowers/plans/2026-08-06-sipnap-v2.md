# SIPNAP v2 — Pemusnahan, Splits, Hard-Blocks, Export History — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend SIPNAP v1 with: destruction records (Pemusnahan) with BAP fields and hard stock decrement, split Pemasukan/Pengeluaran per the official Kemkes form, three continuity hard-blocks, and a stored-snapshot export history.

**Architecture:** Same as v1: Postgres RPC (`get_sipnap_report` v2) + SSR pages + server actions. Export pushes the exact CSV to Supabase Storage (`sipnap-archives` bucket) and stores a URL on the history row. No NestJS.

**Tech Stack:** Next.js 16 App Router, Supabase Postgres (RLS), Supabase Storage, TypeScript 6.x, pnpm 11.

-- 1. Destruction tables (formal legal event with BAP).
CREATE TABLE IF NOT EXISTS public.stock_destructions (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    tenant_id UUID NOT NULL REFERENCES public.tenants(id) ON DELETE CASCADE,
    bap_number VARCHAR(100) NOT NULL,
    bap_date DATE NOT NULL,
    witness_names TEXT NOT NULL,
    reason TEXT NOT NULL, -- EXPIRED | DAMAGED
    notes TEXT,
    created_by VARCHAR(255),
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE IF NOT EXISTS public.stock_destruction_items (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    tenant_id UUID NOT NULL REFERENCES public.tenants(id) ON DELETE CASCADE,
    stock_destruction_id UUID NOT NULL REFERENCES public.stock_destructions(id) ON DELETE CASCADE,
    product_id UUID NOT NULL REFERENCES public.products(id) ON DELETE RESTRICT,
    batch_id UUID NOT NULL REFERENCES public.product_batches(id) ON DELETE RESTRICT,
    batch_number VARCHAR(100) NOT NULL,
    expiry_date DATE,
    qty_destroyed NUMERIC(14,3) NOT NULL
);

ALTER TABLE public.stock_destructions ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.stock_destruction_items ENABLE ROW LEVEL SECURITY;

-- Tenant isolation policies (same guard pattern as the AP migration).
DO $$

            FOR ALL USING (tenant_id = (current_setting('request.jwt.claims', true)::jsonb -> 'app_metadata' ->> 'tenant_id')::uuid);

END $$;

DO $$
BEGIN
    IF NOT EXISTS (SELECT 1 FROM pg_policies WHERE schemaname='public' AND tablename='stock_destruction_items' AND policyname='Tenant isolation for stock_destruction_items') THEN
        CREATE POLICY "Tenant isolation for stock_destruction_items" ON public.stock_destruction_items
            FOR ALL USING (tenant_id = (current_setting('request.jwt.claims', true)::jsonb -> 'app_metadata' ->> 'tenant_id')::uuid);
    END IF;
END $$;

CREATE INDEX IF NOT EXISTS idx_stock_destructions_tenant_id ON public.stock_destructions (tenant_id);
CREATE INDEX IF NOT EXISTS idx_stock_destruction_items_destruction_id ON public.stock_destruction_items (stock_destruction_id);
CREATE INDEX IF NOT EXISTS idx_stock_destruction_items_batch_id ON public.stock_destruction_items (batch_id);

-- 2. SARANA sale type (B2B outbound transfer).
DO $$
BEGIN
    IF NOT EXISTS (
        SELECT 1 FROM pg_enum e
        JOIN pg_type t ON t.oid = e.enumtypid

    ADD COLUMN IF NOT EXISTS generated_by VARCHAR(255),

    ADD COLUMN IF NOT EXISTS payload jsonb;

VALUES ('sipnap-archives', 'SIPNAP Archives', false)

CREATE POLICY IF NOT EXISTS "Tenant read own sipnap-archives" ON storage.objects

- [ ] **Step 2: Rewrite the RPC**

Replace `get_sipnap_report` entirely (same signature `(p_month int, p_year int)`). Read the v1 body first and keep its transaction/missing logic. The v2 body must:

1. Compute per-product, per-source movements:
   - `pemasukan_dari_pbf` = SUM of `goods_receipt_items.qty_received` where the receipt's PO supplier has `is_pbf = true` and `received_at` in month.
   - `pemasukan_dari_sarana` = same where `is_pbf = false`.
   - `pengeluaran_untuk_resep` = SUM of `sale_items.qty_sold` where `sale_type = 'RESEP'` and `sold_at` in month.
   - `pengeluaran_untuk_sarana` = same where `sale_type = 'SARANA'`.
   - `jumlah_dimusnahkan` = SUM of `stock_destruction_items.qty_destroyed` where `bap_date` in month.
   - `status_pemusnahan` = 'ADA' when `jumlah_dimusnahkan > 0`, else 'TIDAK ADA'; include `bap_number`, `bap_date` (join `stock_destructions`).
   - `saldo_awal` = (IN before month, split) − (OUT before month, split) − (destroyed before month) — mirror the v1 opening subquery but include destructions.
   - `saldo_akhir` = saldo_awal + pemasukan_pbf + pemasukan_sarana − pengeluaran_resep − pengeluaran_sarana − jumlah_dimusnahkan.

2. Validation:
   - Keep v1 `missing` (doctor/patient) but make it type-aware: for `sale_type = 'RESEP'` rows require doctor name + SIP + patient name + address; for `sale_type = 'SARANA'` rows require patient (facility) name only — no doctor.
   - `checks` array with three types:
     - `NEGATIVE`: one entry per product where `saldo_akhir < 0` (`{type:'NEGATIVE', product_name}`).
     - `BAP`: one entry when any `stock_destruction_items` in month joins a destruction with NULL/empty `bap_number` (`{type:'BAP'}`). Rare — safety net.
     - `CONTINUITY`: find the latest `sipnap_exports` row for the previous month (`(p_year, p_month-1)` with year rollover). If one exists, read `payload->'products'` (array of `{product_id, saldo_akhir}`) and compare each product's current `saldo_awal`; add one `CONTINUITY` entry per mismatch (`{type:'CONTINUITY', product_name, expected, actual}`). No prior export = no continuity entries.
   - `ready` = `NOT EXISTS(missing) AND NOT EXISTS(checks)`.

3. Return shape:
```json
{
  "month": int, "year": int, "ready": bool,
  "transactions": [...], "missing": [...],
  "checks": [{"type":"NEGATIVE","product_name":""} | {"type":"BAP"} | {"type":"CONTINUITY","product_name":"","expected":0,"actual":0}],
  "products": [{
    "product_id": uuid, "product_name": str,
    "saldo_awal": num, "pemasukan_dari_pbf": num, "pemasukan_dari_sarana": num,
    "pengeluaran_untuk_resep": num, "pengeluaran_untuk_sarana": num,
    "jumlah_dimusnahkan": num, "status_pemusnahan": "ADA"|"TIDAK ADA",
    "bap_number": str|null, "bap_date": str|null,
    "saldo_akhir": num
  }]
}
```
The `transactions` rows gain `sale_type` so the UI can show RESEP vs SARANA detail lines.

```ts
'use server'

import { redirect } from 'next/navigation'
import { createClient } from '../../../../utils/supabase/server'

export async function createDestruction(formData: FormData) {
  const supabase = await createClient()
  const {
    data: { user },
  } = await supabase.auth.getUser()
  if (!user) throw new Error('Not authenticated')
  const tenantId = user.app_metadata?.tenant_id
  if (!tenantId) throw new Error('No tenant context')
  const role = user.app_metadata?.role
  if (role !== 'OWNER' && role !== 'PHARMACIST') throw new Error('OWNER or PHARMACIST only')

  const bapNumber = String(formData.get('bap_number') || '').trim()
  const bapDate = String(formData.get('bap_date') || '').trim()
  const witnessNames = String(formData.get('witness_names') || '').trim()
  const reason = String(formData.get('reason') || '').trim()

  if (!bapNumber || !bapDate || !witnessNames || !reason) {
    throw new Error('BAP number, BAP date, witnesses, and reason are required')
  }

  const productIds = formData.getAll('product_id')
  const batchIds = formData.getAll('batch_id')
  const qtys = formData.getAll('qty_destroyed').map(Number)
  if (productIds.length === 0) throw new Error('Add at least one item')
  if (qtys.some((q) => !Number.isFinite(q) || q <= 0)) throw new Error('Invalid quantity')

  // Load batches and guard qty <= current_qty (same pattern as purchase returns).
  const { data: batches } = await supabase
    .from('product_batches')
    .select('id, batch_number, expiry_date, current_qty')
    .in('id', [...new Set(batchIds.map(String))])
  if (!batches) throw new Error('Failed to load batches')
  const batchMap = new Map(batches.map((b) => [b.id, b]))
  for (let i = 0; i < batchIds.length; i++) {
    const batch = batchMap.get(String(batchIds[i]))
    if (!batch) throw new Error('Batch not found')
    if (qtys[i] > Number(batch.current_qty)) {
      throw new Error(`Destruction exceeds stock for batch ${batch.batch_number}`)
    }
  }

  const { data: header, error: hErr } = await supabase
    .from('stock_destructions')
    .insert({
      tenant_id: tenantId,
      bap_number: bapNumber,
      bap_date: bapDate,
      witness_names: witnessNames,
      reason,
      created_by: user.email || null,
      notes: String(formData.get('notes') || '').trim() || null,
    })
    .select()
    .single()
  if (hErr) throw new Error(hErr.message)

  const itemRows = productIds.map((pid, i) => {
    const batch = batchMap.get(String(batchIds[i]))!
    return {
      tenant_id: tenantId,
      stock_destruction_id: header.id,
      product_id: String(pid),
      batch_id: String(batchIds[i]),
      batch_number: batch.batch_number,
      expiry_date: batch.expiry_date,
      qty_destroyed: qtys[i],
    }
  })
  const { error: iErr } = await supabase.from('stock_destruction_items').insert(itemRows)
  if (iErr) throw new Error(iErr.message)

  for (let i = 0; i < batchIds.length; i++) {
    const batch = batchMap.get(String(batchIds[i]))!
    const { error: uErr } = await supabase
      .from('product_batches')
      .update({ current_qty: Number(batch.current_qty) - qtys[i] })
      .eq('id', String(batchIds[i]))
    if (uErr) throw new Error(uErr.message)
  }

  redirect(`/stock/destructions/${header.id}`)
}
```

### Placeholder scan

### Type consistency

- `SipnapV2Product` / `SipnapCheck` types defined in Task 2, used in Tasks 2+5.
- Check types: `NEGATIVE`, `BAP`, `CONTINUITY` — same strings in RPC and `checksToLines`.

### Known simplification

- Continuity relies on the previous month's stored `payload`; before the first-ever export of a month there is no baseline, so no continuity check fires. Add a daily stock snapshot table when backdated edits become a real risk.
- Destruction records carry no monetary value (qty + batch only). Add unit cost when finance needs destruction write-offs.
- History pagination is page-param based (25/page); fine at 12 rows/year.
